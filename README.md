# لوحة زاد (zad-admin)

لوحة التحكم الداخلية لزاد: Zad Security والشهادات.

- **المرحلة 1 (الأساس):** تسجيل دخول الموظفين، التحقق بخطوتين الإلزامي، الصلاحيات، إدارة الموظفين، وسجل العمليات.
- **المرحلة 2 (Zad Security):** استقبال الطلبات من `zad.gg/security` عبر `/api/ingest/security` (موقّعة بـ HMAC)، صفحة الطلبات بالبحث والفلترة، صفحة تفاصيل (الحالة، المسؤول، الملاحظات، واتساب، السجل)، وتصدير CSV.

- **المرحلة 3 (الشهادات):** تدريب، حضور، كورس. إصدار فردي، وإصدار جماعي من CSV، ومعاينة، وPDF بنفس التصميم (Chromium عبر Playwright)، وتعديل، وإلغاء، وواجهة `/api/public/cert/<code>` لصفحة التحقق `zad.gg/cert/<code>`.

ملفات PDF تحتاج متصفح Chromium مرة واحدة على كل جهاز: `npm run pdf:install`.

للربط محلياً: `INGEST_SECRET` في `.env` هنا = `ADMIN_API_SECRET` في `.env.local` لموقع zad-landing، و`ADMIN_API_URL=http://localhost:3001` هناك.

## التشغيل على جهازك (أول مرة)

### 1. ثبّت MySQL
```bash
brew install mysql
brew services start mysql
```

### 2. ثبّت الحزم
```bash
cd ~/zad-admin
npm install
```

### 3. ملف البيئة
```bash
cp .env.example .env
openssl rand -base64 48
```
افتح `.env` وضع:
- `DATABASE_URL="mysql://root@127.0.0.1:3306/zad_admin"` (على جهازك فقط؛ MySQL من brew بدون كلمة سر لـ root)
- `AUTH_SECRET="..."` الناتج من أمر `openssl` أعلاه

### 4. أنشئ الجداول
```bash
npx prisma migrate dev --name init
```
ينشئ قاعدة `zad_admin` والجداول، ومجلد `prisma/migrations` (ارفعه على git، يحتاجه السيرفر).

### 5. أنشئ حساب المدير الأول
```bash
npm run create-admin -- you@example.com "اسمك"
```
يطبع كلمة مرور مؤقتة.

### 6. شغّل اللوحة
```bash
npm run dev
```
افتح http://localhost:3001 وسجّل الدخول. سيُطلب منك:
1. إعداد التحقق بخطوتين بتطبيق مثل Google Authenticator، واحفظ الرموز الاحتياطية.
2. اختيار كلمة مرور جديدة (12 حرفاً على الأقل).

| الأمر | الوظيفة |

## الأمان (ما تم في المرحلة 1)
- كلمات المرور مشفّرة بـ scrypt، وحد أدنى 12 حرفاً.
- التحقق بخطوتين (TOTP) إلزامي لكل حساب، ومفتاحه مشفّر في القاعدة بـ AES-256-GCM.
- 8 رموز احتياطية لكل موظف، كل رمز لمرة واحدة.
- قفل الحساب 15 دقيقة بعد 5 محاولات خاطئة، وحد لعدد المحاولات من نفس IP.
- الجلسة 12 ساعة، وتتجدد عند اجتياز التحقق بخطوتين، وتُحذف عند تغيير كلمة المرور أو تعطيل الحساب.
- لا يوجد تسجيل مفتوح، ولا يمكن حذف آخر مدير نشط.
- كل عملية حساسة مسجّلة في سجل العمليات مع IP.
- `noindex` ورؤوس أمان (CSP، HSTS، منع الإطارات).

## إذا فقد موظف جواله
- يدخل بأحد رموزه الاحتياطية، أو
- مدير آخر يضغط "إعادة ضبط 2FA" من صفحة الموظفين.

> لا تغيّر `AUTH_SECRET` بعد أن يفعّل الموظفون التحقق بخطوتين، وإلا يحتاج كل حساب إعادة ضبط.
